## 2. 依赖与复现

在配套 CANN 9.1.0 的 Linux NPU 主机执行。CPU torch 源用于 x86_64 开发环境。

```bash
python3.12 -m venv <venv>
source <venv>/bin/activate
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install torch-npu==2.7.1.post8 triton-ascend==3.6.0.post2 numpy==2.5.4 pytest==8.4.2
source /usr/local/Ascend/cann-9.1.0/set_env.sh
export ASCEND_RT_VISIBLE_DEVICES=0 OMP_NUM_THREADS=1 MAX_JOBS=2
git clone --branch feat/token-slot-address-translation https://github.com/TreamTik/xllm.git
cd xllm
git checkout c6f16c8286c798b5a014ce91e07f6c952623d484
export PYTHONPATH="$PWD"
python examples/kernels/token_slot_address_translation/verify.py --mode all \
  --output-dir <results> > <results-log> 2>&1
python -m pytest --noconftest tests/python/test_token_slot_address_translation.py -q
```

首次非空 prepare 仅 JIT 编译所需 Triton 核。首次编译不进入性能计时。
程序在失败时返回非零状态，并在结果目录保留 result.json 和错误信息。
结果、日志、缓存和构建产物放在源码之外。

完整独立归档为 `token_slot_address_translation_selftest.zip`。
归档根目录包含 solution.py、源码路径、fixtures、测试、设计、版本清单和验证原始数据。
解压后使用相同命令，向 verify.py 增加 `--source-manifest source-manifest.json`。
该选项显式使用归档版本清单，运行不依赖 .git 或 server 扩展。

## 3. 精度与工程检查

独立工程复验完成全部 14 个规定正向输入及 10 个非法输入检查。
候选和冻结 NPU 基线均与任务提供的独立 CPU 标杆逐元素一致。
另含 S=3/7/31 近 INT32 输出上界，S=1073741823/1073741824 的大小逻辑输入，
5 个相邻几何/超片上预算输入、合法动态 slots/M 更新和两组 offset=1 存储重绑定。
两组主性能输入分别验证双 stream 各保留 3 份输出、输出互不别名和 20 次释放回收。
精度表中的 47 条为分组检查记录，不表示 47 个互相独立的输入 case。
正式 pytest 入口：1 passed；独立无 Git 工程功能复验：PASS。

非幂二除法使用 INT64 magic 乘法及一次纠正，幂二页长使用 shift。
独立 signed `//` 探针曾在高位整数出现误差，例如 1073741822//1073741823 得到 1；
该实验未进入产品。严格整数路径已通过任务的全部边界。

## 4. 性能

计时入口为完整 prepared.run，包括 Python 提交、独立新输出、当次临时分配、设备执行和最终同步。
输入生成/传输、prepare、CPU 标杆和首次编译排除。两侧分别预热 50 次，交替 6 轮，每轮 200 次。
单轮延迟为 200 次调用与最终同步的墙钟耗时除以 200。
使用全部 6 轮做 10,000 次共同 bootstrap，seed=20261031，分位数线性插值。
主性能同时检查平均节省、中位节省、CI95 下界和 85/155 μs 上限。
S=64/96 两个补充输入只提交配对测量，不套用主性能门槛。
